# GLEE 운영 앱 — 인터뷰 합의 사항

기록일: 2026-09-07. 사용자와의 인터뷰에서 최종 합의한 제품 요구사항이다. 구현 완료를 뜻하지 않는다. 아래와 충돌하는 초기 제안은 이 문서의 결정을 따른다.

## 1. 개발 기준과 기존 작업

- 사용자가 GitHub 기본 브랜치에 버그 수정을 머지했다. 구현 재개 전 최신 기본 브랜치를 확인하고 반영한다. 기존 로컬 변경은 보존한다.
- 기존 프론트 디자인 작업은 제공된 GLEE 로고와 Figma 모바일 UI 키트를 활용한다. 로고는 필요하면 검은 글씨를 유지한 투명 배경으로 만들 수 있다.
- 기존 기능의 불필요한 재검증은 사용자가 원하지 않는다. 새로운 기술 도입이 필요한 경우 이유와 적용 여부를 먼저 논의한다.
- 처음 도입하는 프로그램이므로 과거 출석 데이터의 학기별 이관은 필요 없다. 기존 회계장부는 유지한다.

## 2. 명단과 권한

- 음악 파트·음악 역할과 행정 직군은 별도 속성이다. 서로 겸임할 수 있다.
- 행정 직군은 한 사람당 하나: 단장 / 홍보 / 총무. 단장과 총무는 각각 1명, 홍보는 여러 명 허용한다.
- 역할은 노션 명단에서 관리하고 앱에서 데이터를 다시 불러올 때 변경된 권한을 반영한다.
- 역할 교체 후에는 현재 담당자가 지난 학기 기록도 관리한다. 과거 작성자·업로드자·확인자와 시각은 보존한다.
- 겸임자는 각 역할의 권한을 함께 갖는다.

| 역할 | 권한 |
| --- | --- |
| 모든 단원 | 첫 화면, 일정 캘린더와 상세, 일정 사진, 공연 곡 목록·순서, 재정 조회 |
| 지휘자 | 지휘 탭, 지휘 일정 관리, 곡·공연 연결·자료 관리, 확인 현황 조회 |
| 파트장·반주자 | 지휘 탭에서 자료 열람·확인. 자료 등록·수정·삭제 불가 |
| 단장 | 행정 탭, 행정 일정 등록·수정·삭제·취소, 사진 관리, 학기 마감 |
| 홍보 | 행정 탭, 사진 관리. 일정 관리 불가 |
| 총무 | 재정 항목 추가·수정·삭제, 이월금 확정·재확정 |

지휘자는 출석 대상에서 제외한다. 반주자는 출석에서 일반 단원과 동일하게 취급하며, 기존 합의대로 반주자 출석 확정은 지휘자가 담당한다.

## 3. 첫 화면과 일정

- 첫 화면은 현재 화면 구성을 유지한다. 가장 가까운 예정 일정을 지휘·행정 구분 없이 위에 표시한다.
- 아래 목록도 모든 종류의 앞으로 일정을 가까운 날짜순으로 보여준다. 과거 일정은 첫 화면에서 제외한다.
- 오늘 일정은 시작 시간이 지나도 당일에는 유지한다.
- 여러 날에 걸친 행정 일정은 종료일까지 유지하며, 진행 중인 일정을 앞으로 시작할 일정보다 먼저 표시한다.
- 단장도 출석 탭에서 행정 일정을 등록할 수 있다. 지휘자의 기존 일정 등록 경로도 유지한다.
- 노션 전체 일정 데이터베이스의 분류: 지휘 / 행정. 작성 권한에 따라 정해진다.
- 지휘 일정: 연습 / 정기공연 / 외부공연. 지휘자만 등록·수정·삭제·취소한다.
- 행정 일정: 단장만 등록·수정·삭제·취소한다.
- 연습·공연은 단일 날짜이며 시작 시간이 필수다. 행정 일정은 종일 및 여러 날짜에 걸친 등록을 지원한다.
- 모든 일정에 선택 입력인 설명을 제공한다. 설명은 상세에서 모두에게 공개한다.
- 정기공연과 외부공연 날짜는 캘린더에서 강조한다.
- 캘린더에 과거 일정도 표시한다. 날짜를 누르면 일정이 하나일 때는 바로 상세, 여러 개일 때는 해당 날짜의 목록을 거쳐 상세로 이동한다.
- 첫 화면의 일정도 같은 상세 페이지로 연결한다.
- 공연 상세에 곡 목록과 순서를 모두에게 공개한다. 악보·음원 자료는 지휘 탭 권한이 있는 사람만 볼 수 있다.
- 취소된 일정은 취소 상태로 보존한다. 취소된 연습·공연의 입력된 출석은 삭제하고 출석 통계·미출석 처리에서 제외한다. 취소 일정은 사진 등록 의무에서도 제외한다.

## 4. 출석

- 연습과 공연에 기존 출석 입력·확정 규칙을 적용한다. 행정 일정에는 출석이 없다.
- 지휘자를 제외한 모든 활동 단원이 대상이다. 반주자와 행정 직군 보유 단원도 포함한다.

## 5. 사진과 행정 탭

- 연습·공연·행정 일정 모두 사진이 필수다. 단장·홍보 중 누구든 최소 한 장을 올리면 일정 전체의 의무를 충족한다.
- 여러 날의 행정 일정도 날짜별 한 장이 아니라 일정 전체에 한 장이면 된다.
- 사진은 노션 일정에 저장하고 모든 단원이 상세에서 볼 수 있다.
- 단장·홍보는 서로 올린 사진도 삭제·교체할 수 있다. 업로드자를 기록한다.
- 사진이 없으면 일정 종료일 다음 날부터 단장·홍보 시작 화면에 경고한다. 등록하면 해제한다.
- 모든 사진을 삭제해 다시 사진이 없어지면 같은 기한 규칙에 따라 경고가 재개된다.
- 행정 탭에는 모든 종류의 일정을 함께 표시한다. 사진 등록 기한이 지난 미등록 일정에 빨간 느낌표를 표시하고, 탭에는 해당 일정 개수 배지를 표시한다.
- 이전 학기 미완료 기록은 보존한다. 경고와 배지는 해당 학기를 선택했을 때만 표시한다.

## 6. 공연·곡·자료

- 일정에 필기본을 첨부하는 초기 안은 폐기한다. 전체 곡 데이터베이스와 지휘 탭에서 곡별 자료를 관리한다.
- 기본 탐색 구조: 지휘 탭 → 공연 → 곡 목록 → 곡별 자료. 공연 미정 곡도 관리할 수 있다.
- 곡 하나를 여러 공연에 연결하며 기존 자료를 공유한다. 공연마다 곡 순서를 지휘자가 지정한다.
- 공연 등록 시 전체 곡 데이터베이스에서 여러 곡을 검색·선택한다. 없는 곡은 즉시 새로 등록하고 공연에 연결한다.
- 공연은 곡 없이 먼저 등록할 수 있고 이후 곡을 추가할 수 있다.
- 곡 제목은 필수, 작곡가·편곡자는 선택이다. 선택 목록에도 구분 정보를 표시한다.
- 곡 등록 시 공연을 선택하거나 공연 미정으로 둘 수 있다. 곡 목록·자료는 학기가 바뀌어도 유지하며 학기별 가져오기 절차는 없다.
- 공연 미정 곡은 확인 요구와 미확인 경고 대상이 아니다.
- 필기본은 파트별이 아니라 곡 전체 악보다. 모든 파트장·반주자가 같은 자료를 받는다.
- 업로드 시 교체/별도 추가를 묻지 않는다. 곡별 이전 필기본은 보존하지만 가장 최근 필기본만 확인 대상으로 삼는다.
- MP3 등 음원은 연습 날짜별로 별도 축적한다.
- 지휘자만 자료 등록·수정·삭제 및 확인 필수 여부를 지정한다. 기본값은 필기본 필수, 음원 선택이다.
- 파일 형식: 사진 JPG·PNG·HEIC, 악보 PDF·이미지, 음원 MP3·M4A·WAV. 다른 자료 유형도 확장 가능한 구조로 설계한다.
- 사진·악보·음원과 확인 기록은 노션에 저장한다. 자료별 등록일과 연습 날짜를 구분해서 표현한다.
- 공연이 취소돼도 곡과 자료는 보존한다. 취소된 공연에서만 사용하는 자료는 경고에서 제외한다. 다른 유효한 공연에서 사용하면 확인 의무를 유지한다.

## 7. 자료 확인과 경고

- 필수 자료는 파일을 열어본 뒤 명시적으로 확인 완료 버튼을 눌러야 확인 처리한다. 시각을 기록한다.
- 현재 학기 공연의 자료는 과거 일정에 해당하더라도 확인 대상이다. 새 파트장·반주자도 취임 전 업로드된 현재 학기 자료를 확인해야 한다.
- 새 필기본을 올리면 재확인을 요구하고 이전 버전과 확인 기록은 보존한다.
- 같은 학기·같은 파일은 여러 공연에서 사용해도 한 번만 확인한다.
- 새 학기 공연에 연결된 곡의 필수 자료는 새 학기 기준으로 다시 확인한다. 이전 학기 확인 기록은 보존한다.
- 업로드 즉시 각 대상자의 시작 화면과 지휘 탭에 미확인 경고를 표시한다. 확인하면 해제한다.
- 파트장·반주자의 지휘 탭 배지는 본인의 미확인 필수 자료 수다. 여러 공연에 연결된 같은 자료는 중복 계산하지 않는다.
- 지휘자에게 자료별 확인 인원/대상 인원을 표시한다. 상세에서 미확인자를 먼저 보여주고 확인자는 확인 시각을 표시한다.
- 이전 학기 경고는 해당 학기를 선택했을 때만 표시한다.
- 외부 푸시·문자·카카오톡 알림은 제공하지 않는다. 앱 내부 경고와 배지만 제공한다.

## 9. 학기

- 최초 운영 학기는 2026년 2학기다.
- 시작일·종료일을 사용자가 입력하지 않는다. 단장만 이번 학기 마감하기를 실행한다.
- 다음 학기 이름을 보여주고 한 번 확인받는다. 실행 시점을 종료로 기록하고 다음 학기를 자동 시작한다.
- 이름 순서: 2026년 2학기 → 2027년 1학기 → 2027년 2학기 → ….
- 마감 시 아직 시작하지 않은 일정은 다음 학기로 자동 이동한다. 연결된 공연 곡도 새 학기 확인 대상에 반영한다.
- 진행 중이거나 지난 일정은 기존 학기에 남긴다.
- 단원 명단은 유지하며 역할 변경은 노션에서 관리한다.
- 앱은 현재 학기를 기본으로 보여주고 학기 선택으로 이전 기록을 조회한다.
- 이전 학기를 읽기 전용으로 잠그지 않는다. 현재 담당자가 기존 역할 권한에 따라 수정할 수 있다.
- 자료·사진의 과거 미완료 상태를 보존하되 현재 학기 시작 화면에는 이전 학기 경고를 표시하지 않는다.

## 10. 노션 저장과 실패 처리

- 모든 운영 기록은 노션에 저장하고 페이지 로드 시 노션에서 불러온다.
- 기존 명단·회계장부를 활용하고 전체 일정, 곡 목록, 곡별 자료, 자료 확인 기록, 학기 관리 데이터베이스를 별도로 연결한다.
- 노션 저장에 성공한 후에만 저장 완료로 표시한다. 실패하면 입력 내용을 유지하고 오류와 재시도를 제공한다.
- 노션 조회 실패 시 마지막으로 조회한 데이터를 최신 정보 아님 표시와 함께 보여주고 변경 작업을 막는다.
- 남아 있는 조회 데이터가 없다면 재시도 화면을 표시한다.

## 구현 전 확인할 기술 사항

다음 항목은 기능 추가에 대한 새 합의가 아니라 구현에 필요한 연결·API 확인 사항이다.

- 최신 기본 브랜치와 로컬 작업 차이, 기존 명단·출석 노션 구조와 연결 설정.
- 노션 파일 업로드의 실제 제한, HEIC·음원 미리보기 지원 방식. 지원 불가능한 경우 사용자에게 대안을 설명한다.
