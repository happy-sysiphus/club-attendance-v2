# 합창단 출석 관리 — 프런트엔드 설계 스펙

작성일: 2026-08-23
상태: 확정 (구현 전)
전제: 백엔드 스펙 `2026-07-24-attendance-backend-design.md`의 13개 API를 그대로 사용. 백엔드 로직 변경 없음.

## 1. 목적과 범위

연습장에서 휴대폰으로 쓰는 출석 운영 화면. 역할 3종(단원·파트장·지휘자)의 모든
흐름을 이번에 구현한다: 로그인 → 본인 예정 상태 입력 → 파트장 확인 → 지휘자 마감.

## 2. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 스택 | 순수 HTML + CSS + JS(ES 모듈), 빌드 없음, 의존성 0 | FastAPI 정적 서빙 그대로, Render 배포 스크립트 변경 없음 |
| 구조 | 단일 SPA, 해시 라우팅 | 사용자 선택. 화면 4개, 공유 헤더·토스트 한 벌 |
| 디자인 | 팔레트 A "클래식 콘서트" — 네이비 `#1F2A44` + 골드 `#C9A227` + 아이보리 `#F7F4EC` | 합창단 아이덴티티 반영, 사용자 선택 |
| 대상 기기 | 모바일 우선(360px~), 데스크톱은 max-width 640px 중앙 정렬 | 연습장 휴대폰 사용이 주 |
| 실시간 | 현황판 5초 폴링(`setInterval`), 뷰 이탈 시 정지 | 백엔드 설계와 일치 |

## 3. 파일 구조와 백엔드 변경

```text
app/static/
  index.html    # 셸: 헤더 + <main id="view"> + 토스트 영역 + <script type="module" src="app.js">
  app.js        # 해시 라우터 + 뷰 4개 렌더 함수 + 상태 폼 컴포넌트
  api.js        # fetch 래퍼, 세션 저장소(localStorage), 라벨·포맷 상수
  style.css     # 디자인 토큰 + 컴포넌트
```

백엔드 변경은 `main.py` 한 곳: `register_routes(app)` 뒤에
`app.mount("/", StaticFiles(directory=<app/static 절대경로>, html=True))`.
API 라우트가 먼저 등록되므로 `/practices` 등은 API로, 나머지는 정적 파일로 간다.
`GET /` → `index.html`. 정적 디렉터리 경로는 `__file__` 기준 절대경로(실행 위치 무관).

## 4. 라우팅과 세션

라우트: `#/login` · `#/home` · `#/practice/:id`(단원 본인 입력) · `#/board/:id`(현황판).
해시 없음 또는 알 수 없는 해시 → `#/home`.

세션 쿠키는 httponly라 JS가 읽을 수 없다. 따라서:

- 로그인 응답 `{member_id, name, part, role}`을 `localStorage.session`에 저장.
- 라우터는 진입 시 `localStorage.session`이 없으면 `#/login`으로 보낸다.
- `api.js`는 모든 응답에서 **401이면 `localStorage.session` 삭제 후 `#/login`** 이동.
  쿠키 만료(180일)·비활성 처리·서버 재배포 후 SECRET_KEY 변경 전부 이 한 경로로 처리.
- 로그아웃 버튼 = `localStorage.session` 삭제 + `#/login`. (쿠키는 httponly라 JS로 못
  지우지만, 서버는 세션 저장소 없이 서명만 검사하므로 클라이언트 상태 삭제로 충분.)
- 역할 분기(버튼 노출)는 `session.role`로만 한다. 권한의 진짜 검증은 서버(403)이며,
  403이 오면 토스트로 `detail`을 보여준다.

## 5. 화면 상세

### 5.1 로그인 `#/login`

- 상단 앱 이름, 이름·학번 입력 두 개(큰 터치 영역), "로그인" 버튼.
- `POST /auth/login`. 401 → 입력 아래 "명단에 없어요. 이름과 학번을 확인하세요." 인라인.
- 성공 → 세션 저장 → `#/home`.
- 이미 세션이 있으면 `#/home`으로 즉시 이동.

### 5.2 홈 `#/home`

공통 헤더: 앱 이름 · `이름 · 파트 · 역할` · 로그아웃.

위에서부터 세 블록. 데이터: `GET /practices`, `GET /me/stats` 병렬 호출.

1. **다음 연습 카드** — 선택 규칙: `status=open`이면서 `starts_at >= 오늘 00:00`인 것 중
   가장 이른 연습. 없으면 `open`인 것 중 가장 최근. 그것도 없으면 카드 숨김.
   내용: 제목, `M/D (요일) HH:MM`, 장소. 버튼은 역할별:
   - 단원 → "내 출석 입력" → `#/practice/:id`
   - 파트장·지휘자 → "현황판" → `#/board/:id`
   (파트장·지휘자도 단원으로서 본인 입력이 필요하므로 "내 출석 입력" 버튼도 함께 노출.)
2. **내 출석률 카드** — `rate`는 소수(0.875)이므로 `Math.round(rate*100)`% 크게,
   아래에 `출석 n · 지각 n · 결석 n / 총 n`. `total=0`이면 "아직 마감된 연습이 없어요".
3. **연습 목록** — 서버 순서(최신순) 그대로. 행: 제목, 날짜시간, 상태 배지
   (`open`=진행중, `closed`=마감·회색 처리). 행 탭 = 다음 연습 카드와 같은 역할별 이동.
   마감된 연습: 단원은 `#/practice/:id`(읽기 전용으로 결과 확인), 스태프는 현황판.

지휘자 전용:
- 헤더 아래 "새 연습" 버튼, 각 연습 행에 수정·삭제 아이콘(`open`일 때만).
- 연습 폼은 네이티브 `<dialog>`: 제목(필수), 시작(`<input type="datetime-local">`, 필수),
  장소. `datetime-local` 값 `YYYY-MM-DDTHH:MM`을 `starts_at`으로 그대로 전송
  (서버 `fromisoformat`이 수용). 수정 시 서버 값 `YYYY-MM-DDTHH:MM:SS`에서 앞 16자를
  폼에 채운다.
- 삭제는 `confirm()` 확인 후 `DELETE`. 409(마감됨) → 토스트.

### 5.3 내 출석 입력 `#/practice/:id`

데이터: `GET /practices`(목록에서 해당 연습 찾기 — 단건 GET API 없음), `GET /practices/:id/me`.

- 상단: 연습 제목·시간·장소.
- **상태 폼(공용 컴포넌트)**: 출석/지각/결석 세그먼트 버튼 3개.
  - 지각 선택 → 사유(텍스트, 필수) + 도착 예정(`<input type="time">`, 필수) 노출.
  - 결석 선택 → 사유(텍스트, 선택) 노출.
  - 출석 → 부가 입력 없음.
  - 저장 버튼. 클라이언트에서 지각 필수값 비면 버튼 비활성(서버 422도 토스트로 처리).
- `PUT /practices/:id/me` 성공 → "저장됐어요" 토스트 + 폼에 응답값 반영.
- **잠금 조건**(폼 비활성 + 안내문):
  - `practice.status === 'closed'` → "마감된 연습입니다."
  - `now >= starts_at`(클라이언트 시계 기준) → "연습이 시작돼 파트장·지휘자만 수정할 수 있어요."
  - 클라이언트 시계가 틀려 잠금 판단이 어긋나도 서버 403/409가 토스트로 잡는다.
- 현재 상태 표시: `status` null이면 "미입력", `source === 'auto'`면 "결석(자동)".
  지각이면 사유·도착 예정 함께.

### 5.4 현황판 `#/board/:id` (파트장·지휘자)

데이터: `GET /practices/:id/board` — 진입 시 1회 + 5초마다. 단원이 접근하면 403 →
토스트 후 `#/home`.

레이아웃(위→아래):

1. **연습 헤더**: 제목, 시간, 장소, 상태 배지. 지휘자는 여기에 마감/재오픈 버튼(아래).
2. **전체 집계 칩** 4개: 출석 n · 지각 n · 결석 n · 미확정 n (`totals`).
   파트장은 자기 파트 집계만 오므로 그대로 표시.
3. **파트 섹션** (파트장 1개, 지휘자 4개 — soprano, alto, tenor, bass 순):
   - 헤더: 파트 한글명, 집계 요약, 확인 상태.
     - `confirmed=true` → "확인 완료" 배지.
     - `false` → "확인 완료" 버튼 → `confirm()` → `POST /part/confirm {part}`.
       파트장은 자기 파트만, 지휘자는 4파트 모두 버튼 노출(대행).
   - 단원 행 정렬(**"확인 필요 우선형"**): 미확정 → 지각 → 결석 → 출석, 같은 그룹 안은
     서버 순서(이름순). 처리할 사람이 맨 위에 온다.
   - 행: 이름 · 상태 칩 · (지각) `사유 · 도착 HH:MM` · (결석) 사유 · `source=auto`면
     "자동" 표시. `status=null`은 "미확정" 칩(연습 시작 전에만 나타남).
   - 행 탭 → **상태 수정 시트**(`<dialog>`, 5.3과 같은 상태 폼 컴포넌트). 저장 →
     `PUT /practices/:id/members/:member_id` → 성공 시 즉시 재조회(다음 폴링 안 기다림).
     시트가 열려 있는 동안 폴링 결과는 목록에만 반영하고 시트 입력값은 건드리지 않는다.
     마감된 연습이면 행 탭 비활성.
4. **지휘자 전용**:
   - **마감 버튼**: 4파트 모두 `confirmed`일 때만 활성. 미확인 파트가 있으면 비활성 +
     "소프라노·테너 확인 대기" 문구. 클릭 → `confirm("마감하면 미확정 단원은 결석 처리됩니다")`
     → `POST /close`. 409 → 토스트(`detail.missing_parts` 한글 변환).
   - **마감 후**: 배지 "마감". `notion_synced_at`이 null이면 "노션 동기화 중…" 문구와
     함께 "동기화 재시도" 버튼(= `POST /close` 재호출, 멱등)을 항상 노출 — 응답에
     `closed_at`이 없어 경과 시간을 알 수 없으므로 타이머 없음. 정상이면 폴링 한두 번
     안에 값이 채워져 "노션 동기화 완료 HH:MM"으로 바뀐다.
   - **재오픈 버튼**(마감 상태일 때): `confirm()` → `POST /reopen`.
   - `roster_warnings`가 비어 있지 않으면 상단에 노란 배너로 나열(노션 명단 오류).

## 6. 공통 UI 규칙

- 상태 칩 색은 팔레트와 무관하게 고정: 출석 초록 `#2E7D4F`, 지각 호박 `#B7791F`,
  결석 빨강 `#B3261E`, 미확정 회색 `#6B7280`. 색 + 텍스트 라벨 병기(색맹 대비).
- 라벨 매핑 상수(`api.js`):
  `PART = {soprano:'소프라노', alto:'알토', tenor:'테너', bass:'베이스'}`,
  `ROLE = {member:'단원', part_leader:'파트장', conductor:'지휘자'}`,
  `STATUS = {present:'출석', late:'지각', absent:'결석', null:'미확정'}`.
- 시간 표시: `starts_at`(`YYYY-MM-DDTHH:MM:SS`, KST 나이브)을 `new Date(str)`로 파싱
  (타임존 접미사 없는 ISO는 로컬로 해석되므로 한국 기기에서 KST와 일치) →
  `M/D (요일) HH:MM`. 다른 시간대 기기는 범위 외.
- 디자인 토큰(`style.css` `:root`): `--navy #1F2A44`(헤더·주 버튼), `--gold #C9A227`
  (강조·활성 세그먼트), `--ivory #F7F4EC`(페이지 배경), `--card #FFFFFF`,
  `--ink #1C1C1C`, `--muted #6B7280`. 터치 타겟 최소 44px. 본문 16px.
  글꼴: 시스템 한글 스택(`-apple-system, "Apple SD Gothic Neo", "Malgun Gothic",
  sans-serif`) 기본. 제목용 디스플레이 서체 1종은 구현 시 frontend-design 스킬
  판단에 따라 Google Fonts 1개까지 허용(없어도 됨).
- 토스트: 우하단 고정, 3초 후 자동 소멸, 에러는 빨강 테두리. 한 번에 하나.
- 빈 상태·로딩: 첫 로드는 "불러오는 중…" 한 줄, 목록 비면 "연습이 없어요".

## 7. 데이터 흐름과 에러 처리

```text
api.js
  request(method, path, body?) → fetch(credentials 'same-origin', JSON)
    ├ 401 → session 삭제 → location.hash='#/login' → throw
    ├ !ok → throw Error(detail 문자열화)   # 객체 detail({missing_parts})은 호출자가 처리
    └ ok  → json
  session(): localStorage.session 파싱 / setSession / clearSession
app.js
  route(): hash 파싱 → 이전 뷰 cleanup(폴링 clearInterval) → 뷰 렌더
  뷰 = async 함수: 데이터 fetch → innerHTML 템플릿 리터럴 → 이벤트 바인딩
  statusForm(initial, {locked}) → DOM 조각 + read() (5.3·5.4 공용)
  toast(msg, {error})
```

- 폴링 실패(네트워크) 시 토스트는 띄우지 않고 다음 주기에 재시도. 헤더에 "마지막 갱신
  HH:MM:SS"를 표시해 멈춤을 눈으로 알 수 있게 한다.
- 뷰 렌더는 통째 `innerHTML` 교체. 현황판 폴링 재렌더는 열린 `<dialog>`를 보존하기
  위해 목록 영역(`#board-list`)만 교체한다. 상태 수정 `<dialog>`는 `#board-list`의
  형제 요소로 한 번만 만들어 두고, 행 탭 시 내용만 채워 `showModal()`한다.
- XSS 방지: 서버 데이터(이름·사유·제목)를 템플릿에 넣을 때 `esc()` 헬퍼로 이스케이프.

## 8. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 폴링 중 쿠키 만료 | 401 → 로그인으로. 폴링은 뷰 이탈 cleanup으로 정지 |
| 연습 시작 시각이 폴링 도중 지남 | 서버가 null→결석(auto)로 계산해 내려주므로 재렌더만으로 반영 |
| 단원이 시작 직전에 저장 → 서버는 이미 시작 | 403 토스트 + 폼 잠금 전환 |
| 마감 버튼 활성인데 그 사이 재오픈·확인 변경 | 서버 409 토스트 후 즉시 재조회 |
| 존재하지 않는 연습 id(삭제됨) | 404 토스트 → `#/home` |
| `roster_warnings` 존재 | 현황판 상단 배너(지휘자만 옴) |
| 지휘자가 본인 출석 입력 | 일반 단원과 같이 `#/practice/:id` 사용 (시작 후엔 현황판에서 수정) |

## 9. 검증

- pytest 1개 추가: `GET /` → 200, `text/html`, 본문에 `<main id="view">` 포함.
  `GET /practices`는 여전히 API(정적 마운트가 API를 가리지 않음)도 같은 테스트에서 확인.
- 프런트 로직 검증은 브라우저 패널 시나리오(노션 없이 `python -m app.main` 기동,
  `demo.db`에 역할 3종 계정 준비):
  1. 단원 로그인 → 지각 입력(사유·ETA 누락 시 버튼 비활성) → 저장 → 새로고침 유지
  2. 파트장 로그인 → 현황판에 지각자 상단 노출 → 타 단원 결석 처리 → 파트 확인 완료
  3. 지휘자 로그인 → 연습 생성·수정 → 4파트 확인 대행 → 마감 → 재오픈 → 재마감
  4. 단원이 `#/board/:id` 직접 접근 → 403 토스트 → 홈
  5. 모바일 뷰포트(375px)에서 모든 화면 가로 스크롤 없음
- JS 테스트 프레임워크·린터는 추가하지 않는다.
